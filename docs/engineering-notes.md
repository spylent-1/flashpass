# 业务映射与工程记录

## 从查询到预约

| 预约语义 | 当前兼容模型 |
| --- | --- |
| 活动场馆或资源展示 | `Shop`、`ShopType`，沿用 `tb_shop` 等表 |
| 营销权益与活动名额 | `Voucher`、`SeckillVoucher` |
| 名额申请记录 | `VoucherOrder` |

本轮不迁移表名或更改既有 URL，避免仅改文案就破坏数据库映射。领域模型与 API 的完整预约化将作为独立开发任务推进。

## 本轮工程改动

- 将本地已有登录、Token、空值缓存和同步申请代码整理到公开版本。
- 根目录可以直接运行 Maven，Java 包迁移到 `io.github.spylent1.flashpass`，同步 Mapper XML 与实体别名。
- 应用名、构建坐标、启动类、SQL 文件统一使用 FlashPass 命名。
- 移除 IDE 工程文件，数据库凭据、Redis 连接与上传目录由环境配置。
- Redisson 与 Spring Redis 共用连接属性，避免两个客户端连接不同实例。

## 需要继续完成的正确性工作

同步申请目前先扣库存再检查重复，返回业务失败可能提交前面的扣减；重复检查也缺少数据库唯一约束，不能声称已实现预约幂等。后续需明确失败回滚、唯一约束与重试策略，并覆盖重复申请时库存不变、并发不超卖等测试。

Redisson 客户端和若干缓存工具已存在，但不代表已接入预约并发控制或缓存重建主链路。开发验证码保存在 Session，登出接口尚未完成。

## 后续验收场景

取消后返还名额、候补按顺序补位、超时回收只执行一次、重复消息不重复建单、消费者失败后可重试且库存一致。上述场景需要实现后再更新状态。
